# 天色 · 需求与决策规格

> 版本 v1.0 · 2026-11-17
> 本文是**功能与行为的唯一依据**，界面外观见 [DESIGN.md](./DESIGN.md)。
> 标注「已拍板」的条目不得在实现时自行更改；标注「默认值」的可调整。

---

## 1. 产品定义

**天色（Tianse）** 是一个 Windows 桌面护眼工具。它做三件事，并且只做这三件事：

1. **调色温** —— 按用户所在地当天的真实日出日落，把屏幕色温从白天 6500K 平滑降到夜间 3400K。
2. **调亮度** —— 按同一条曲线同步压低屏幕背光，相对用户原始亮度乘系数。
3. **切明暗** —— 天色转暗时把 Windows 明暗主题切成深色，天亮切回浅色。

不做：20-20-20 提醒、护眼操、蓝光检测、屏幕使用时长统计、视力测试。这些是另一类产品。

**目标用户**：长时间在电脑前、对夜间屏幕刺眼敏感、愿意装一个常驻小工具的人。

## 2. 技术栈（已拍板）

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | Go 1.26 | 单文件产出、Win32 调用成熟、无运行时依赖 |
| 框架 | Wails v3.1.0 | 自带系统托盘与 WebView2 窗口，无需额外 systray 库 |
| 前端 | Vue 3 + Vite + TypeScript | 与 Wails 模板一致，构建产物内嵌进 exe |
| 窗口 | Wails v3 实心无边框窗口，固定 900×620 | 磨砂由 CSS 内部模拟，不做真透明（见 §5.1） |
| 色温实现 | Win32 `SetDeviceGammaRamp` | 零延迟、逐屏独立、不改驱动设置 |
| 亮度实现 | DDC/CI 优先，失败回落 Gamma 缩放 | 真背光调节最省电；Gamma 兜底保证功能可用 |
| 明暗实现 | 写 HKCU 注册表 + 广播 `WM_SETTINGCHANGE` | 系统级、所有应用跟随 |

**明确不做**：不申请管理员权限（UAC）、不覆盖登录界面、不装驱动、不注入进程。

## 3. 核心算法（已拍板）

### 3.1 色温曲线
- 白天固定 **6500K**（不高于，避免偏冷刺眼）。
- 夜间目标 **3400K**。
- 起算点：**日落前 2 小时**开始下降，日落后 30 分钟到达最低；日出对称反向。
- 过渡用**余弦缓动**：`t = (1 - cos(π · p)) / 2`，p 为进度 0→1。相比线性，两端更平缓，人眼不易察觉切换。
- 色温 → RGB 用 **Tanner Helland 黑体辐射近似**，再做亮度归一（保证三通道和不变，避免调色温时屏幕变暗）。
- 每秒重算一次；与上次写入值差异 **< 1%** 时跳过写入。

### 3.2 日出日落
- 用 **Meeus 日出方程**（与 sunrise-sunset.org 误差 1 分钟内）。
- 极昼/极夜返回 `ErrNoSunriseSunset`，此时退化为固定色温，并在界面提示可切固定时间表。

### 3.3 亮度
- 公式永远是 **面板目标 = 基线 × 系数**。变的是基线从哪来，不是公式。
- **基线二选一**（`brightness.baseline`，已拍板）：
  - `panel`：基线 = 面板满亮（1.0）。系数 100% 就是面板 100%，界面自解释。
  - `startup`：基线 = 启动时读到的 DDC 读数。系数是「相对你开机时屏幕有多亮」。
  - 新装默认 `panel`；老配置升级默认 `startup`（升级瞬间屏幕不动）。
- **安全下限：基线的 30%**（已拍板）。低于此值强制停在 30%。滑块可设 5%–100%。
- 变化 **≥ 3%** 才写 DDC/CI（单次写入可能 50–100ms，必须放独立 goroutine，绝不阻塞 UI 线程）。
- **手调接管**：每 30 秒空闲时读一次当前亮度，与上次写入值相差 > 5% 视为用户手动改过，**该屏本次运行不再写**（状态卡「亮度已手动接管，改设置即恢复」）。保存设置即解除接管。

### 3.4 明暗滞回
- 色温 **≤ 4500K** 转深色，**≥ 5200K** 回浅色。中间区间保持现状，避免临界点反复横跳。
- 与色温曲线的平滑过渡**解耦**：明暗是离散事件，不做渐变。

### 5.1 界面风格拍板（2026-11-17 追加，用户 m00368）

用户要求「整体界面风格使用磨砂玻璃的感觉，需要一种模糊不刺眼的温润的感觉」。结论：

| 项 | 结论 | 理由 |
|---|---|---|
| **磨砂的实现方式** | **实心窗口 + CSS 内部模拟六层**，不做真透明 | ① WebView2 不支持半透明背景（`DefaultBackgroundColor` 只接受 alpha 0 或 255）② Win10 无系统级 Mica/Acrylic（需 Win11 22621+）③ Win10 私有 API 拖动掉帧 ④ 透明窗口 `WS_EX_TRANSPARENT` 会点击穿透 ⑤ 玉面不透明度 < 0.93 时文字对比度跌破 4.5 |
| **窗口背景类型** | Wails v3 `BackgroundTypeSolid`，**不启用** `BackgroundTypeTranslucent` / `BackdropType` | 同上；避免点击穿透与 DWM 合成开销 |
| **视觉隐喻** | 「玉」而非「玻璃」：有厚度、有内部光、有颗粒，光进不来也出不去 | 真玻璃要透，透就控不住对比度；玉是实心的，观感同样温润 |
| **色板变更** | 深色墨灰 `#758A99` → **`#879BAA`**；浅色天水碧 `#2F7E88` → **`#2A747D`**；浅色缃 `#A87A1E` → **`#8F660F`** | 玉面比玄亮，原色值在玉面上对比度不足（详见 DESIGN §2.3） |
| **新增表面色** | 玉面 `#1D2025` / 浮起 `#202429` / 按下 `#181B20` / 凹槽 `#161B20` | 用同一块玉的厚度差代替「卡片 + 阴影」 |
| **天光染色** | 玉面色相随当前天色漂移，**恒亮度 Y=0.014** | 只换色相不动亮度，四个文字色对比度在所有天光下完全恒定 |
| **布局**（2026-11-17 追加，用户 m00508） | **卡片式多层次**：四张卡（读数 720×128 L2 / 天光轴 720×168 L1 / 开关 460×176 L2 / 状态 240×176 L1），卡间距 20，**不做等分网格** | 等分网格像仪表盘，大小不等的卡能一眼分出主次；卡片用颜色深浅分层，不用投影 |
| **圆角** | 卡 **12** / 元件 **8** / 胶囊半高 **10** / 圆点 **50%**，不做圆角嵌套 | 统一小圆角，不堆叠大圆角；禁止「玻璃卡片 + 阴影 + 大圆角」的默认玻璃拟态 |

### 5.2 主题色随时间漂移拍板（2026-11-17 追加，用户 m00580）

用户要求「不要局限于一个主题色，可以根据时间变化动态变化软件的主题色」。结论：**做，但必须源色预补偿**。

| 项 | 结论 | 理由 |
|---|---|---|
| **漂移方式** | 强调色随色温**在显示端**从 H187（青）漂到 H159（海绿），饱和度 34→40，**亮度 Y 恒定 0.31781** | 恒亮度保证对比度不变；青→海绿是低色温下唯一可达的方向 |
| **源色预补偿** | **必须做**。CSS 源色 = 目标显示色 ÷ 当前 Gamma 增益，逐通道上限 255 | 不补偿的话 3400K 下 `#5AA4AE` 显示成 `#5A7A5C`（H124 S15%），被洗成死灰，对比 3.67 |
| **为什么不漂到靛蓝** | 3400K 蓝通道增益只有 135，需要源色 B=328 才能显示成靛蓝，**物理不可达** | 通道上限 255，钳位后仍是灰绿 |
| **补偿范围** | **只补偿前景**（强调色 + 墨灰）；背景（玄/玉面/霜）**不补偿** | 前景要可读；背景随屏幕变暖是正确的，那是「纸」在灯光下的样子 |
| **墨灰补偿** | 只放大不改色相，使显示端恒 **5.00**（3400K 需 1.15×） | 补偿后低色温显示为暖褐 `#9C8568`，是屏幕本来的样子 |
| **缃 / 月白** | **不补偿**（最坏 5.67 / 9.26，本来就够） | 避免不必要的复杂度和钳位风险 |
| **浅色侧** | 补偿幅度很小（0.86×–1.03×），**色相不漂移** | 浅底对比余量大；霜底上的强调色一变绿，玉的冷感就没了 |
| **判定基准** | 正文文字 **4.5:1**，非文字 UI 组件（强调色）**3:1** | WCAG 1.4.11；早期误用 4.5 导致算出「3400K 无可行色相」 |
| **实现方式** | 5 个锚点（6500/5725/4950/4175/3400），Go 端按 `p` 做 **RGB 线性插值** | 实测插值 vs 精确曲线最大 ΔE **1.16**、色相误差 **1.11°**，肉眼不可分辨，不需要样条 |
| **计算位置** | Go 端算好 `--accent` / `--ink` / `--xiang` 三个 CSS 变量推给前端 | 色温曲线唯一真相在 Go 端，前端不跑颜色计算 |
| **已知代价** | 低色温下 CSS 源色出现高蓝值（3400K 强调源 `#49E4FF`）→ **截图不代表实际观感** | 用户截图发到未调色温的机器上会明显偏蓝，这是预补偿的必然代价 |

### 5.3 界面补充拍板（2026-11-17 追加）

| 项 | 结论 | 理由 |
|---|---|---|
| **设置页形态** | **同窗口第二页**，900×620 不变，标题栏不变；齿轮进入、字标位置的 chevron 返回；横向滑入 240ms | 不新增窗口就不新增一套标题栏与关闭语义；两页一个字符串状态，**不引入路由** |
| **设置页范围（首版）** | 位置（含**开机自启**）/ 色温 / 亮度 / 明暗 / 关于；多屏独立配置、固定时间表**留到下一版** | 首版把「会让主界面行为变化」的项收齐即可，其余是低频配置。自启在实现时并入位置卡（同属「这台机器的事实」），见 DESIGN §4.5 |
| **设置页栅格** | 两列 **460 + 240**，与主界面同栅格；左列可操作（L2 玉面）、右列只读（L1 沉） | 「左边改东西、右边看东西」与主界面「开关卡 460 / 状态卡 240」同一个分法 |
| **天光轴跨度** | **日落前 2 小时 → 日出后 2 小时**（曲线的肩部），不是日入→日出 | 日入→日出时色温在日落后 30 分钟就到底，**约 73% 的轴是纯 3400K 平色**，看不出天色在变；取肩部后两端正好 6500K，全轴都在变化 |
| **轴上标注** | 只有「日入 / 现在 / 日出」三处；带的两端不写时间 | 两端是肩部不是事件，写上去就是第四、第五个数字抢注意力 |
| **天光轴色带亮度** | 深色 Y = **0.075** / 浅色 Y = **0.42 + 彩度补偿 1.3** | 深色侧与卡面 2.1:1；浅色侧方向翻转（纸面上没有比纸更亮的颜料），无彩度补偿会得到一条灰褐带 |

### 5.4 运行时语义补充拍板（2026-11-17 追加）

| 项 | 结论 | 理由 |
|---|---|---|
| **全屏挂起** | 检测到全屏独占应用即**让出屏幕**：恢复原始 Gamma、亮度回基线，退出后 2 秒线性平滑恢复；明暗不动 | 游戏/播放器自己管画面，此时改写 Gamma 是干扰；状态卡显示「全屏中 / 让出屏幕」而不是时钟 |
| **挂起判定** | `SHQueryUserNotificationState` 的 QUNS_BUSY / QUNS_RUNNING_D3D_FULL_SCREEN，再叠加「前台窗口**四边都贴近**其所属显示器的矩形」（每边绝对差 ≤ 2px），且窗口不带 `WS_MAXIMIZE` 样式 | 单用窗口矩形会把任务栏缩略图悬停误判成全屏（LightBulb #411）；单用 QUNS 在某些播放器里不报。**「至少和显示器一样大」这个判据是错的**：Windows 把最大化窗口画到显示器外约 8px，四条不等式对最大化窗口恒成立，于是任何最大化窗口都被当成全屏 |
| **时刻显示时区** | 所有面向用户的时刻（轴上的日入/现在/日出、状态卡的下次切换、整点刻度）一律按**本机本地时区**格式化，走 `internal/clock` | `suncalc` 内部算的是 UTC instant，直接 `Format("15:04")` 打印的是 UTC 墙钟——北京会差 8 小时，表现为「日入 09:11 / 日出 22:41」这种反了的时间 |
| **自启读取源** | 读注册表 HKCU\…\Run，不读配置文件 | 清理工具或手工编辑会删掉 Run 项，界面必须显示事实而不是上次的选择 |
| **诊断子命令** | `tianse.exe --diagnose` 打印环境报告后退出：系统版本 / 会话与交互式桌面 / 配置目录可写 / 每屏 device·分辨率·DDC 三元组·Gamma 读写探针 / 夜间模式注册表 / WebView2 版本 / 结论行 | 本产品的失败模式几乎全是环境而非逻辑，从外部看都是「不工作」；报告把每一项变成具名的「是/否」 |
| **测试范围** | 只测纯逻辑：色温映射与增益、调色板锚点与对比度、日出日落（Meeus）、曲线插值与相位、滞回 | 平台层（Gamma/DDC/注册表）无法在 CI 里断言，靠 `--diagnose` 与人工验收 |
| **首次启动** | 提示卡替换读数卡（同尺寸同位），不做浮层、不做向导、不做「重新运行」入口；`App.FirstRun` 置 false 即永不再现 | 620 高度按像素排，插条会压掉 56；城市未确认时读数卡上的色温本来就是错的读数，换掉比压住更诚实 |
| **读数卡亮度显示** | 自动亮度开着 → 报目标值；关着但面板答 DDC/CI → 报面板回报值；面板拒绝 DDC → `不可控`；面板无可控背光 → `—` | 「功能关闭」不是「读不到」：把关闭画成破折号会让用户以为亮度不可知。只有真的没有数字时才不给数字 |

## 6. 默认值（可调整，不再逐条询问）

1. **亮度基线漂移**：每 30 秒空闲时读一次，与上次写入差 > 5% 视为用户手动改，基线更新为该值。
2. **全屏恢复**：退出全屏后 **2 秒内**线性恢复，恢复过程同样受 3% 节流约束。
3. **用户手动改系统主题**：检测到后自动降级为「跟随系统」，弹一次性气泡告知。
4. **多屏时的天光轴**：主屏显示，副屏配置在设置页内切换查看。
5. **首次启动**：不做多页向导。读数卡整块换成等尺寸提示卡（720 × 128，同一位置），一句话陈述「按某城市的日落工作」+ 换个城市 / 自动亮度 / 开机自启 / 开始使用四个控件；关闭后换回读数卡。自动亮度默认关，首次启动是唯一一次能当面说明它存在且有兼容性风险的时机。理由见 DESIGN §4.6。
6. **失败判定**：只有 **Gamma 写入失败**才进失败态（托盘图标变灰 + 断点标记）。DDC 失败但 Gamma 成功时，状态行显示「亮度不可控」，不进失败态。
7. **日志**：`%APPDATA%\Tianse\logs\tianse.log`，单文件 1 MB 轮转，保留 3 份，默认 INFO。
8. **更新机制**：无自动更新。绿色版手动替换，安装包手动下载。
9. **辅助功能**：遵循系统「高对比度」与「减少动画」设置（后者对应 `prefers-reduced-motion`）。
10. **配置文件 schema**：见第 7 节，里程碑 1 开始前定稿。

## 7. 配置文件 schema

路径 `%APPDATA%\Tianse\config.yaml`。所有字段都有默认值，文件缺失或损坏时用默认值重建并备份损坏文件为 `config.yaml.bak`。

```yaml
version: 1                    # schema 版本，用于迁移

location:
  city: "杭州"                # 城市名，仅用于显示
  latitude: 30.2741
  longitude: 120.1551
  timezone: "Asia/Shanghai"   # IANA 时区名

temp:                         # 色温
  enabled: true
  day: 6500                   # 白天色温 K，范围 5000-6500
  night: 3400                 # 夜间色温 K，范围 2000-4000
  start_before_sunset_min: 120 # 日落前多少分钟开始过渡
  settle_after_sunset_min: 30  # 日落后多少分钟到达最低

brightness:
  enabled: false              # 默认关，因为 DDC/CI 有兼容性风险
  day_ratio: 1.0              # 白天系数（相对基线）
  night_ratio: 0.45           # 夜间系数
  floor_ratio: 0.30           # 安全下限，硬编码兜底也是这个值
  step_threshold: 0.03        # 变化多少才写 DDC/CI

theme:                        # 明暗
  enabled: false              # 默认关；首次启动卡与设置页各有一个开关，见 DESIGN §4.6
  mode: "follow_sky"          # follow_sky | follow_system | always_light | always_dark
  dark_at_k: 4500             # 降到该色温转深色
  light_at_k: 5200            # 升到该色温回浅色

schedule:
  mode: "sun"                 # sun | fixed
  fixed:                      # mode=fixed 时使用，24 小时制
    night_start: "19:00"
    night_end: "07:00"

displays:                     # 多屏，键为显示器设备名
  "\\.\DISPLAY1":
    sync: true                # true 时忽略下面的独立配置
    temp_offset: 0            # 独立模式下的色温偏移
    brightness_ratio: 1.0

ui:
  theme: "auto"               # auto(跟随天色) | light | dark
  accent_drift: true          # 强调色随色温漂移（青→海绿），关掉则固定 6500K 基准色
  last_page: "main"

app:
  autostart: false
  pause_until: null           # RFC3339，临时暂停到期时间
```

**迁移规则**：读到 `version` 小于当前版本时，按版本顺序逐级迁移；大于当前版本时，不覆盖，提示「配置来自更新版本」。
